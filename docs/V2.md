# v2 release notes

Breaking changes are intentional: legacy tokens are no longer accepted; sessions use HTTP-only cookies. Clients must send credentials and an exact Origin for mutations. Signup now takes JSON and omits avatar upload. Listings use explicit title/description/price/images/condition/size fields rather than product_* fields and untyped details arrays. Currency is LKR; unsafe EUR charging and hardcoded buyer-protection/shipping fees are removed.

Existing prototype data is not migrated, reset or deleted. For a clean development setup select a new database name in MONGODB_URI. Legacy records will not meet the v2 contract and are not supported without a separately planned migration. No real-world provider availability or business policy is assumed.

Payment is deliberately a disabled provider boundary. Future implementation requires authenticated orders, server-side pricing in integer minor units, single-item reservations, verified idempotent webhooks, refunds and payout/settlement support. A client-controlled amount must never be reintroduced. Supply real gateway account settings only after choosing and verifying a provider.

Regression tests cover wrong-password rejection, correct login, private session cookies, origin checks, logout/revocation, expiry before TTL deletion, invalid/missing uploads, local image publishing/serving, shared listing fields, Unicode input, literal search, sorting, bounded pagination and disabled charging.
